# v1.00 Overview — Core Factory Validation

## Version Purpose

Ship the smallest complete Tiny Factory that can prove whether rolling machines and rebuilding visible production chains is intrinsically fun.

## Primary Validation Question

> **Is building a factory from random machines fun enough that players repeatedly change their layouts?**

## Scalability Objective

Create one reliable, persistent, server-authoritative factory simulation capable of supporting the core loop without committing to a large logistics engine.

## Player-Facing Objective

A player can:

- watch items spawn
- watch machines visibly transform them
- earn Coins
- roll a machine
- place/move/remove machines
- discover better orders
- expand capacity a few times
- leave and return to the saved factory

## Architecture Objective

Establish:

- deterministic single-route simulation
- reusable machine definitions/behaviors
- authoritative economy
- inventory and placement services
- schema-versioned persistence
- analytics event layer
- active-item/performance safeguards

## Planned Phases

1. Factory Simulation Foundation
2. Building & Placement
3. Rolling, Inventory & Economy
4. Launch Machine Set & Synergies
5. Persistence, Analytics & Security
6. Release Polish & Validation

## Expected Content

Provisional launch target:

- 1 plot
- 1 route
- 1 terminal seller bay with rollable alternatives
- 8 droppers and 8 sellers per rarity, plus existing upgraders
- 1 currency
- 3–4 capacity states
- polished readable HUD/build/roll/inventory UI on desktop/mobile
- modeled water-island environment and readable machine families
- essential effects/audio

The earlier small content target is superseded by the approved catalog expansion. Balance and art acceptance remain required.

## Current Status and Completion Phases

**Incomplete / Needs Work.** Read `MVP-Audit.md` for evidence and `MVP-Completion-Plan.md` for required Phases 7–10: island world, machine modeling, UI/audio/balance, deployed MVP acceptance. Automated Phase 1–6 passes are foundation evidence, not release approval.

## Analytics Goals

Measure:

- first sale/roll/place timing
- rolls per session
- layout changes
- machines placed/moved/sold
- machine usage
- expansion
- production milestones
- quit points
- return behavior

## Economy Considerations

Free rolls use a server cooldown; Coins fund capacity.

No prestige. No secondary currency. No paid luck.

## Security Risks

- spoofed sale value
- roll manipulation
- free-roll spam
- invalid placement
- machine duplication
- currency edits
- remote flooding
- save rollback/conflict

## Performance Risks

- excessive item count
- per-machine heartbeat loops
- physics/collision overhead
- high-frequency replication
- noisy effects
- save payload growth

## Manual Validation Requirements

- first-minute comprehension
- desktop building feel
- mobile building feel
- machine readability
- factory ordering value
- saving across reconnects
- multiplayer isolation
- performance under item cap
- economy pacing

## Deferred Systems

- modular conveyor graphs
- splitters/mergers
- multiple lines
- research
- prestige
- visiting
- trading
- events
- live config
- social progression

## Technical Exit Criteria

All must be true:

- production pipeline runs reliably
- all launch machines process correctly
- layouts save/load
- inventory cannot trivially duplicate
- rolls and sales are server-authoritative
- placement is validated
- economy transactions are consistent
- mobile building is functional
- analytics events are firing
- save schema supports migration
- item cap/performance safeguards work
- relevant automated checks pass

## Product Validation Criteria

Use real player data. Suggested metrics are **provisional**, not automatic success thresholds.

Evidence should show that players:

- understand the loop
- roll and place several machines
- voluntarily reorganize working factories
- experiment with more than one ordering
- reach at least one capacity expansion
- remain engaged long enough to make optimization decisions
- show meaningful return behavior

The strongest signal is repeated **layout modification**, not raw playtime.

## Failure Response

If the loop does not validate:

1. identify friction vs concept failure
2. improve readability/building/roll agency if those are the blockers
3. simplify weak systems
4. retest
5. pivot or stop if repeated tests show the factory itself is not compelling

Do **not** automatically build v2.00.
